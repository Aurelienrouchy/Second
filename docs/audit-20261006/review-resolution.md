# Intégration de la seconde revue

Les deux revues ont porté sur le commit de première livraison `7551244971b19efb0269df15a35e48763c273bc3`. Chaque relecteur a examiné un domaine réalisé par un autre lot. Les constats de cette cible restent dans [review-media-security.md](review-media-security.md) et [review-offers-finance.md](review-offers-finance.md) ; le présent suivi décrit les corrections ultérieures, sans modifier rétroactivement leurs conclusions.

Rendu via SDK authentifié, octets en mémoire, cache désactivé et réponses tardives ignorées | Tests pure parser/rendu/auth/logout/refresh/upload ; le serveur peut générer des tokens objet. Les anciens liens ne sont pas révoqués ; runtime HTTP Storage non disponible |
| Médias R2/R7 : écritures directes contournant promotion/verrou | Toute écriture Firestore article passe par callable. Le client actif utilisait déjà ce contrat pour édition et suppression douce. Storage sans pointeur ne peut rechercher des transactions par query ; objets legacy restent une limite de migration |

Deux compléments de validation ont été intégrés : adaptateur Stripe par plateforme conservant le SDK natif et fermant explicitement les opérations web ; isolation des futurs brouillons locaux par UID et garde des travaux asynchrones à changement de compte. Les anciennes clés/fichiers locaux ne sont ni lus ni supprimés ni migrés automatiquement.

Les deux tests SDK offres initialement ignorés ont été exécutés sur le serveur Firestore officiel Google Cloud 1.22.0, projet `demo-second` en loopback. Les règles Firestore sont exécutées séparément des tests Admin, qui les contournent. [emulator-verification.md](emulator-verification.md) explique le refus réseau canonique, le canal officiel disponible, les empreintes et la limite Storage.

La validation globale du code final, ses empreintes et les commits d'intégration figurent dans [verification.json](verification.json), [source-manifest.json](source-manifest.json) et [commits.md](commits.md). Les tests de cette seconde passe complètent les assertions existantes ; aucun test n'a été retiré pour obtenir une suite verte. Aucune publication, migration distante ou opération réelle de paiement n'a été réalisée.
